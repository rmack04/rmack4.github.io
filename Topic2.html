What Does a Web Server Do?

A web server is responsible for receiving requests from browsers and returning website information. When someone enters a website address, the browser communicates with a server to request content.

Web servers can deliver HTML, CSS, JavaScript, images, and other files. They can also send requests to application servers when additional processing is needed.

What Happens When You Visit a Website?

Several steps take place when someone opens a website.

  1. DNS helps the browser find the IP address connected to the website name.
  2. The browser establishes a connection to the server. HTTPS normally uses TLS to protect communication.
  3. The browser sends an HTTP request to the server.
  4. The server decides whether to return a file, redirect the request, or forward it to an application.
  5. The server sends an HTTP response back to the browser.

Static and Dynamic Content

Web servers can provide two common types of website content: static and dynamic.

Static Content Dynamic Content
Content that already exists as a file. Content generated when a request is received.
Examples include HTML, CSS, images, and fonts. Examples include account dashboards, search results, and shopping carts.

How Web Servers Handle Multiple Users

Popular websites can receive requests from many users at the same time. Web servers use different approaches to manage these connections.

  • Process-based: Uses operating system processes to handle work.
  • Thread-based: Uses multiple threads within processes.
  • Event-driven: Uses an event loop to manage many connections efficiently.

Nginx is known for its event-driven architecture, while Apache supports different processing models.

Web Server Security

Security is important because web servers communicate with users and sometimes handle private information. HTTPS uses TLS encryption to help protect data during communication.

Common Security Practices

  • Updating server software
  • Using HTTPS connections
  • Protecting sensitive files
  • Monitoring server logs
  • Controlling user access
